# hi-log

> 跨平台高性能日志查看 / 检索工具 —— 极致内存占用,极速检索体验

## 项目简介

hi-log 是一个面向开发者与运维人员的日志分析工具,支持 Windows / Linux / macOS。
以 Rust 编写,专注于**超大日志文件**场景:GB 级文件秒开、低内存常驻、毫秒级检索响应。

区别于传统日志工具,hi-log 原生支持 **CLI / AI 工具集成**:AI 助手可通过命令行直接标记日志、写入备注,人在 GUI 中点击标记即可快速定位,实现"AI 分析 + 人工确认"的高效协作流。

## 设计目标

| 目标 | 说明 |
| --- | --- |
| 极致内存 | 内存映射 + 按需加载,文件大小不占内存;常驻内存目标 < 250MB |
| 极速检索 | 后台增量索引,10GB 文件秒开,全文正则检索随打随出 |
| 多端一致 | 三平台同一套 UI 与交互,渲染 60fps |
| AI 原生 | CLI 一等公民,AI 工具可读写标记、触发检索 |

## 核心功能

### 1. 日志检索
- 支持**正则表达式**检索,同时支持多关键字组合(AND/OR)
- 检索结果可**固定(Pin)为快照视图**:主日志继续滚动/追加,快照保持不变,多个快照并存、标签页切换
- 实时跟踪模式(tail -f),新日志流入时自动匹配当前检索条件
- 检索结果高亮 + 上下文快速跳转
- 搜索命中面板 / 侧栏支持拖拽调整大小,并可弹出为独立窗口(多窗口同步)

### 2. 标记系统(Marks)
- 任意日志行可**标记固定**,支持自定义颜色分组
- 标记可附带**备注(Note)**:记录结论、待办、上下文
- 标记面板集中管理,**点击标记秒级跳转**到对应行
- 标记持久化保存(sidecar 文件或项目数据库),重开文件自动恢复
- 标记可导出 / 分享(JSON),便于团队协作

### 3. CLI 与 AI 集成
- 完整 CLI,GUI 的全部核心能力(打开、检索、标记、跳转)均可命令行驱动
- CLI 与运行中的 GUI 实例通过本地 IPC 通信:命令行打标,界面实时高亮
- 面向 AI 工具(Claude Code 等)设计:AI 分析日志后直接落标记 + 备注,人工点击确认
- (规划)MCP Server 模式,作为 AI 编辑器的标准工具接入

CLI 设计草案:

```bash
hi-log open app.log                          # 打开文件(GUI 未启动则拉起)
hi-log search "OutOfMemory" --regex --pin    # 正则检索并固定为快照
hi-log mark app.log:1048576 -m "OOM 首次出现" --color red
hi-log marks list                            # 列出全部标记
hi-log export marks --format json            # 导出标记供 AI/脚本消费
```

## 技术选型

- **语言**:Rust(性能、内存安全、跨平台)
- **UI**:Tauri 2 + React 18 + TypeScript(Vite 构建)
- **核心**:memmap2(内存映射)、regex-automata(检索引擎)、稀疏行索引
- **存储**:SQLite(标记 / 快照持久化)

### UI 框架(已定):Tauri 2 + React + TypeScript

以**多端一致性 + 生态丰富度**为首要标准选定 Tauri 2。重活全在 Rust core(加载、索引、检索),WebView 只作"视口",只渲染可见行,性能与内存可控。

备选触发条件:内存目标压不下去 → 回退 egui;WebKitGTK(Linux)踩坑严重 → 换 Electron。UI 层与核心层严格分离,替换成本可控。详细设计见 [docs/DESIGN.md](docs/DESIGN.md)。

## 架构设计(初步)

```
┌────────────────────────────────────────────────────┐
│  ui/(React 前端:虚拟滚动日志视图 + 面板)            │  ← 前端(Tauri WebView)
├────────────────────────────────────────────────────┤
│  src-tauri/(Tauri 壳:commands / events / 单实例)    │  ← 应用服务层
│  hi-log-cli(本地 socket 转发 → GUI)                 │
├────────────────────────────────────────────────────┤
│  hi-log-core(纯 Rust 库,UI 无关)                   │
│  文件加载(memmap)· 稀疏行索引 · 检索引擎 · 标记      │
├────────────────────────────────────────────────────┤
│  SQLite(标记 / 快照持久化)· 本地 socket(CLI↔GUI)   │
└────────────────────────────────────────────────────┘
```

关键技术点:
- **虚拟滚动**:只渲染可视区域的行,行数不撑爆内存
- **内存映射**:文件不读入内存,操作系统按需分页
- **增量索引**:后台线程建索引,检索与 UI 互不阻塞
- **单实例 + IPC**:CLI 命令转发给已运行的 GUI,标记实时可见

## 性能指标(目标)

- 10GB 日志文件打开 < 1s(SSD)
- 1GB 全文正则检索 < 2s
- 常驻内存 < 250MB(WebView 基线,不含 OS 页缓存)
- 滚动 / 检索动画 60fps

## Roadmap

- [x] **M1** 核心库:大文件加载 + 基础查看(只读、行号、虚拟滚动)
- [x] **M2** 检索引擎:正则检索 + 快照固定(编码检测、主题)
- [x] **M3** 标记系统:标记 / 备注 / 面板跳转 / 持久化(SQLite)
- [x] **M4** CLI + IPC:CLI 驱动 GUI,单实例
- [x] **M5** AI 集成:标记导出格式稳定化,MCP Server
- [x] **M6** 打磨发布:三端打包、自动更新、tail 模式、文档

### M5 / M6 交付内容

- **标记导出**:`hi-log export marks <file>` 直读 SQLite 输出 JSON(标记 + 固定),供 AI/脚本消费
- **MCP Server**:`hi-log mcp` 以 stdio JSON-RPC 提供 open_file / search / get_lines / mark_line / list_marks / pin_line / list_pins 工具,AI 助手(Claude Code 等)可直接分析日志并落标记
- **tail 模式**:状态栏 📡 开关,文件追加自动加载,视口跟随底部,激活搜索自动重扫
- **自动更新**:Tauri updater 插件(需发布服务器与签名,见 [docs/PUBLISH.md](docs/PUBLISH.md))
- **三端打包**:tauri.conf.json bundle 配置(NSIS/MSI,Linux deb/AppImage,macOS dmg 需对应平台构建)
